## Projects slice

- List: compact header and Create project form, Search/archived controls, then readable project cards with name/description and clearly scoped linked-item counts. Show specific loading, successful empty and failed-read states. Retry re-fetches only; create/archive/save use existing mutations and pending/error handlers. Keep current routes, selected project state and typed-name deletion confirmation intact under Settings.
- Selected project: retain All projects, project identity/description and existing tabs. Overview order: **Needs your attention → Continue this project (existing Assistant link) → Task progress → linked-item summary**. Make attention links and new actions 44 px targets. Empty attention says nothing in the returned view needs attention; it does not imply all global work is done.
- Keep task statuses operational: Finished/Running/Waiting/Failed. Link tasks and runs to existing on-demand checks; do not add one verification fetch per row or derive confirmed badges from lifecycle counts. Pending files say requested/waiting, never “file exists.” Existing workspace “Checked by you,” agent assumptions and numerical warnings remain distinct from platform action checks.
- Preserve every hub tab/settings form and workspace control. No new ID picker, project auto-linking, auto-archive, second shared-memory store, automatic file read or permission grant. Linking and data mutations keep their existing payloads and ownership checks.

## Assistant slice

- Keep one h1, full-page main chat and the existing ChatTab instance/identity/storage keys. On desktop the main chat is flexible and the supporting column stays about 22rem; on phone use one column with the chat first. Reorder the supporting column **Changes → Suggestions → Workflow drafting** so outstanding Apply/Reject/Undo controls are easier to find. Do not hide these controls behind interface-level folds or replace their confirmations.
- Show helper/model readiness from successfully loaded existing records, with separate loading/error/empty states and links to existing setup screens. Define agent as AI helper and model as AI brain in relevant guides. Do not auto-select a new provider/model, send a setup prompt or connect anything.
- Relabel the existing project selector as applying to **new** conversations. Existing conversations display project context only when resolved from server data through existing conversation/related hooks; if unavailable, say context could not be checked. Never infer membership from a query parameter. Choosing a project alone does not create, reassign or switch conversations. Use existing explicit New conversation selection; retain unsent text/attachments and existing session-storage behavior.
- Keep source lists/temporary attachment retention, upload state, citation meaning, Knowledge Center switch, before/after proposals, service-confirmed success and exact restricted-action refusals. Workflow drafts stay unsaved until the owner saves in the editor. Suggestions remain user-triggered; no automatic draft/model call on load, refresh or project switch.
- Make fetch failures for helpers/projects/suggestions/change history explicit without disabling unrelated working panels. On action-state refresh failure, show unavailable/stale state rather than presenting a fallback proposal as freshly confirmed; avoid new duplicate Apply controls. Keep all server stale-proposal/owner-proof checks. Do not change the interpreter's routing, ask: behavior, attachment bypass or existing failed-lookup fallback policy in a visual slice; any safety concern is a separately recorded backend proposal.
- Use shared QueryStatus only where it can describe this exact query; show refresh/error and last successful update time from TanStack Query. Do not merge unrelated queries into one global green-ready status. No streaming/regeneration/message edit/retry semantics or optimistic “done” messages are added.
